# 01_岗位画像与复习路线

## 一、后训练算法实习岗位一般做什么

后训练算法实习的核心工作是把一个 **pretrained base model**（只会续写文本）通过一系列训练和对齐技术，变成一个 **有用、安全、能遵循指令的 assistant**。

具体工作内容可能包括：

1. **SFT 数据构造与训练**：构造高质量指令微调数据，跑 SFT 训练
2. **偏好数据构造**：构造 chosen/rejected 对，用于 DPO 等偏好优化
3. **DPO/RLHF 训练**：跑 DPO/PPO/GRPO 等对齐训练
4. **评测体系搭建**：设计 LLM-as-Judge pipeline、自动评测 + 人工抽检
5. **安全对齐**：red teaming、refusal training、幻觉检测与修复
6. **RAG 增强**：检索增强生成，降低幻觉
7. **数据闭环**：线上反馈 → 数据清洗 → 下一轮训练
8. **模型部署与压测**：LoRA merge、vLLM 部署、吞吐/延迟优化

---

## 二、和预训练算法实习的区别

| 维度 | 后训练实习 | 预训练实习 |
|------|-----------|-----------|
| 数据规模 | 几K~几百K | 几T~几百T tokens |
| 算力需求 | 单卡/几卡可跑 | 几百~几千卡集群 |
| 训练目标 | 对齐人类偏好、遵循指令 | 语言建模（next token prediction） |
| 核心挑战 | 数据质量、偏好对齐、幻觉控制 | 训练稳定性、分布式、数据配比 |
| 典型算法 | SFT、DPO、PPO、GRPO | 大规模分布式训练、MoE |
| 你匹配度 | star:5 | star:3 |

---

## 三、和推理部署实习的区别

| 维度 | 后训练实习 | 推理部署实习 |
|------|-----------|-------------|
| 核心工作 | 训练模型让他更好 | 让模型跑得更快更省 |
| 核心技能 | SFT/DPO/RLHF 算法、数据工程 | CUDA/TRT/vLLM/SGLang 优化 |
| 典型产出 | 更好的模型权重 | 更低的延迟、更高的吞吐 |
| 你匹配度 | star:5 | star:3（有 vLLM 部署经验） |

---

## 四、和 RAG 应用实习的区别

| 维度 | 后训练实习 | RAG 应用实习 |
|------|-----------|-------------|
| 核心工作 | 优化模型本身 | 优化检索 + 提示工程 |
| 是否改模型权重 | 是 | 通常不改 |
| 典型算法 | DPO/PPO | embedding/search/rerank |
| 你匹配度 | star:5 | star:4（Safety-RAG 经验） |

## 六、面试一般分几类

1. **基础八股**（20%）：Transformer、Attention、Tokenizer、Softmax、Cross Entropy
2. **后训练算法**（30%）：SFT、DPO、RLHF、GRPO、RLVR、OPD
3. **项目深挖**（25%）：医学 LLM 项目全流程追问
4. **手撕代码**（15%）：DPO loss、SFT loss、Attention、KV Cache、LoRA merge
5. **PyTorch 训练工程**（5%）：显存优化、混合精度、OOM 排查、DP 策略
6. **RAG 设计**（3%）：检索策略、chunking、rerank、hybrid retrieval
7. **评测设计**（1%）：LLM-as-Judge、safety review、pairwise vs score-based
8. **部署压测**（1%）：vLLM、PagedAttention、吞吐/延迟

## 七、针对你的项目，应该怎么突出优势

### 你的最大优势（和同类候选人相比）：

1. **有完整的后训练闭环**：不是只跑了一个 SFT 脚本，而是 teacher 数据生成 → SFT → DPO → LLM-as-Judge → Safety-RAG → vLLM 部署
2. **有自己的发现**：DPO 后在医疗长尾上出现幻觉 → 引入 Safety-RAG → 幻觉下降 66.7%
3. **有安全对齐意识**：在医疗高风险场景下设计了 medical safety review
4. **有部署能力**：LoRA merge + vLLM + 吞吐/延迟压测
5. **有工程能力**：手写过 DPO loss，理解 token logprob gather，理解 QLoRA 显存构成
6. **有辅助项目验证基础**：MiniMind 从零训练小模型

### 面试时的叙述逻辑：

"我做了一个完整的医疗 LLM 后训练和对齐项目，使用 Qwen3-8B 作为基座模型，通过 teacher 模型生成高质量医学回答，经过严格质量过滤后构造约 58K SFT 数据，使用 QLoRA 进行 SFT 训练。然后让 SFT 模型采样构造 rejected，teacher 答案作为 chosen，构造约 10K DPO 偏好对进行偏好优化。评测阶段使用 LLM-as-Judge 进行三类评测。关键发现是 DPO 在提升平均分的同时，在部分高风险医疗长尾问题上产生了严重幻觉。为此我设计了 Safety-RAG 系统，使用 hybrid retrieval + rerank + safety_rules，在案例验证中幻觉下降 66.7%。最后通过 LoRA merge + vLLM 部署完成了端到端交付。"

## 八、哪些地方不能夸大

| 话题 | 不要说的 | 应该说的 |
|------|---------|---------|
| PPO/GRPO | "我训练过PPO" | "我了解PPO/GRPO原理，MiniMind项目有简化实现参考，但我的医学项目没有使用PPO/GRPO" |
| OPD | "我做了OPD" | "我理解OPD是on-policy distillation，我的teacher数据生成是offline版的，后续可以升级为OPD" |
| 线上部署 | "我部署了线上系统" | "我使用vLLM在本地RTX 5090完成了部署和压测" |
| 用户反馈 | "我有用户反馈数据" | "我基于评测结果做了case analysis" |
| 临床验证 | "经过医生验证" | "评测基于LLM-as-Judge和规则检查，未经过医生人工审核" |
| 3 个样本 | "我的幻觉率降低了66.7%" | "在3个高风险案例验证中，RAG后纠正了2个，幻觉下降66.7%，这是案例验证而非统计结论" |
| 大规模 | "我训练了大规模医疗模型" | "我在约58K SFT样本和约10K DPO对上完成了8B模型的QLoRA微调" |

## 背诵版总结

1. 后训练算法实习的核心：把 base model 变成 assistant（SFT → DPO/RLHF → RAG → 评测 → 部署）
2. 你的最大优势：完整的 teacher 数据生成 → SFT → DPO → LLM-as-Judge → Safety-RAG → vLLM 闭环
3. 不能夸大：没做过的 PPO/GRPO/OPD 明确说"了解原理但未实现"
4. 第一优先级：SFT、DPO、LoRA、RAG、LLM-as-Judge、医学项目
5. 面试叙述逻辑：teacher 数据 → SFT → DPO → 发现幻觉 → RAG 修复 → 部署
