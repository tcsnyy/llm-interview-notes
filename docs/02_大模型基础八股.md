## 1. Decoder-only LM

### Q: 为什么现在的 LLM 都是 decoder-only 的？star:4

现在的 LLM（GPT、Llama、Qwen、DeepSeek）几乎都是 decoder-only 架构，即只用 Transformer 的 decoder 部分。对比 encoder-decoder（如 T5），decoder-only 的优势在于：

1. **统一处理所有任务**：不管是分类、生成、翻译还是对话，都可以用统一的 autoregressive 范式处理
2. **训练效率高**：所有 token 在一次前向传播中同时参与训练（teacher forcing），不需要 encoder 的额外开销
3. **扩展性好**：scaling law 在实践中验证 decoder-only 在更大规模下表现非常好
4. **上下文利用**：causal attention 保证每个位置只能看到之前的 token，天然适合生成任务

Encoder-decoder（如 T5、BART）并非不好，而是在需要双向上下文理解的任务（如翻译、摘要）上天然有优势——encoder 可以双向看。但对于 LLM 的场景，我们希望通过一个模型统一所有任务，decoder-only 更简洁。

在我两个项目中都使用 decoder-only 架构：医学项目使用 Qwen3-8B，MiniMind 项目从零实现了 decoder-only Transformer。

**注意**：不要把 decoder-only 说成"只有 decoder"——它用的是 Transformer 的 decoder 层结构（causal self-attention），cross-attention 被移除。也不要说"decoder-only 效果更好"——在不同场景下有不同的最优选择。

## 2. Causal LM / Autoregressive Generation

### Q: 什么是 Causal Language Model？star:4

Causal LM 是指模型在生成第 t 个 token 时只能看到前 t-1 个 token，不能看到未来的 token。数学上：

$$P(x) = \prod_{t=1}^{T} P(x_t | x_{<t})$$

这就是自回归生成。训练时通过 causal mask（下三角矩阵）实现，推理时逐个 token 生成直到遇到 EOS。

**注意**：Causal LM 不等于 Causal Inference（因果关系推断），面试时别混淆。"autoregressive"不意味着"只能从左到右"——也有从右到左的变体。

## 3. Token / Vocabulary / Context Window

### Q: token 和 word 有什么区别？中文 tokenization 有什么问题？star:3

- **Token**：模型处理的最小语义单元，可能是词、子词或字符
- **Vocabulary**：所有 token 的集合，Qwen3-8B 的 vocab size 约 152K
- **Context Window**：模型一次能处理的最大 token 数，Qwen3-8B 是 32768

中文 tokenization 的问题：
1. 中文词边界不明确，分词错误会传播到下游
2. 医学术语（如"脑出血"、"MRSA"）可能被切成多个 token，影响模型理解
3. 中文的 token 效率低于英文（同样意思的中文用更少 token，但每个 token 的信息密度更高）

在我的医学项目中，使用 `tokenizer.apply_chat_template` 确保训练和推理格式一致。

## 4. Logits / Softmax / Cross Entropy

### Q: 模型最后一层输出的是什么？loss 怎么算？star:5

模型最后一层输出的是 **logits**，形状为 `[batch_size, seq_len, vocab_size]`。

- Logits 是未归一化的分数，每个位置有 vocab_size 个分数
- 经过 Softmax 变成概率分布：$\text{softmax}(x_i) = \frac{e^{x_i}}{\sum_j e^{x_j}}$
- 训练时用 Cross Entropy Loss：$L = -\sum_{t} \log P(y_t | x, y_{<t})$
- 实际实现只对目标 token 位置计算 loss，忽略 -100（ignore_index）

**追问：SFT 中为什么要把 user prompt 部分的 label 设为 -100？**

因为我们只想让模型学习如何回答，不想让模型学习如何提问。把 prompt 部分 label 设为 -100，PyTorch 的 CrossEntropyLoss 会自动跳过这些位置。

**手撕代码**：
```python
# Cross Entropy from scratch
def cross_entropy(logits, labels, ignore_index=-100):
    """
    logits: [batch_size, vocab_size] 或 [batch_size * seq_len, vocab_size]
    labels: [batch_size] 或 [batch_size * seq_len]
    """
    # 过滤 ignore_index
    mask = (labels != ignore_index)
    active_logits = logits[mask]   # [num_active, vocab_size]
    active_labels = labels[mask]   # [num_active]

    # Softmax + log
    log_probs = torch.log_softmax(active_logits, dim=-1)  # [num_active, vocab_size]
    # Gather 正确 token 的 log prob
    nll = -log_probs[torch.arange(len(active_labels)), active_labels]  # [num_active]
    return nll.mean()
```

## 5. Perplexity

### Q: PPL 是什么？它能不能衡量模型好坏？star:3

Perplexity = $\exp(\text{cross entropy loss})$，直观上可以理解为模型对下一个 token "平均有几个选择"：

- PPL=1 说明模型对每个 token 都 100% 确定
- PPL=10 说明模型平均要在 10 个选项中猜

**PPL 的局限**：
1. PPL 只衡量语言建模能力，不衡量回答质量、安全性、有用性
2. 低 PPL 不代表模型好——可能只会生成简单的"我不知道"
3. 不能用于比较不同 tokenizer 的模型

在医学项目中，我没有用 PPL 作为核心评测指标，而是使用 LLM-as-Judge（8 维度打分 + pairwise + safety review）。

## 6. 采样参数：Temperature / Top-k / Top-p / Repetition Penalty

### Q: temperature=0 和 temperature=1 有什么区别？star:4

**Temperature**：
- softmax 前将 logits 除以 T：$\text{softmax}(z/T)$
- T→0：退化为 greedy decoding（确定性，选择概率最高的）
- T=1：原始概率分布
- T→∞：趋于均匀分布（随机性极高）
- 我的项目中推理用 temperature=0.2（偏保守）或 0.7（生成 rejected 时增加多样性）

**Top-k**：只保留概率最高的 k 个 token，其余设为 -inf

**Top-p（nucleus sampling）**：按概率从高到低累加，直到累积概率 >= p，只保留这些 token

**Repetition Penalty**：对已经出现过的 token 降低其 logits，防止重复生成

在我的项目中：
- Teacher 答案生成：temperature=0.2（保证质量）
- Rejected 采样：temperature=0.7, top_p=0.8, top_k=20（增加多样性，让 rejected 有"错误空间"）

## 7. Pretrain / CPT / SFT / DPO / RLHF 的区别

### Q: 从 pretrain 到最终 assistant，中间经过哪些阶段？star:5

```
Pretrain（预训练）:
  数据：海量互联网文本（几T tokens）
  目标：next token prediction
  输出：Base Model（会续写，不会对话）

CPT（Continual Pre-Training，继续预训练）:
  数据：领域文本（如医学文献、法律文书）
  目标：next token prediction
  作用：注入领域知识

SFT（Supervised Fine-Tuning，指令微调）:
  数据：高质量 (instruction, response) 对
  目标：next token prediction（只对 response 部分）
  作用：让模型学会对话格式和遵循指令

DPO/RLHF（偏好对齐）:
  数据：偏好对 (prompt, chosen, rejected)
  目标：让模型更偏好 chosen 类回答
  作用：对齐人类偏好，提升有用性和安全性
```

## 8. Base Model / Chat Model / Instruct Model 的区别

### Q: Base model 和 instruct model 本质区别是什么？star:4

- **Base Model**：只会续写文本，不知道什么是"对话"，可能输出不安全的续写
- **Instruct Model**：经过 SFT，能遵循指令，但可能在偏好上不是最优（过于冗长、不够安全等）
- **Chat Model**：经过完整的 SFT + RLHF/DPO，既能遵循指令又对齐了人类偏好

我的项目就是"让 Base Model 变成 Medical Instruct/Chat Model"的过程：Qwen3-8B 是 base model → 我的 SFT 让它变成 medical instruct model → 我的 DPO 让它对齐医疗问答偏好。

## 9. 为什么后训练能让 Base Model 变成 Assistant

### Q: 后训练到底改变了模型的什么？star:5

后训练主要改变了两件事：
1. **格式对齐**（SFT）：让模型学会对话格式（user/assistant 交替）、输出风格、领域知识
2. **偏好对齐**（DPO/RLHF）：让模型的输出分布向"好回答"倾斜，远离"坏回答"

本质上，pre-training 给了模型知识和语言能力，post-training 教会模型"如何用好这些能力"。

**注意**：不要说"后训练教会了模型新知识"——后训练的知识注入很有限，主要知识来自预训练。也不要说"SFT 让模型变聪明"——是让模型学会输出格式和风格。

## 背诵版总结

1. Decoder-only 是主流 LLM 架构，优势在统一任务、训练高效、扩展性好
2. Causal LM 本质是 $P(x_t|x_{<t})$，通过 causal mask 实现
3. Token 不是 word；中文 tokenization 有特殊问题
4. Logits → Softmax → Cross Entropy：SFT 中 prompt 部分的 label=-100
5. PPL 不能衡量回答质量，只是语言建模指标
6. Temperature 控制随机性，Top-p 控制候选集大小
7. Pretrain → SFT → DPO/RLHF 是标准后训练管线
8. 后训练改变的是"格式"和"偏好"，不是"知识"
