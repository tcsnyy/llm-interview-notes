## Day 1：大模型基础 + Transformer + Tokenizer

### 复习目标
- 建立大模型训练全流程的 mental model（预训练 → SFT → RLHF → 部署）
- 能对着白纸画出 Transformer 结构图（Encoder/Decoder/Cross-Attention 区别）
- 能解释 BPE vs WordPiece vs SentencePiece 的区别，以及 tokenizer 对训练的影响

### Q1: GPT 系列 vs LLaMA 系列 vs Qwen 系列的架构差异是什么？⭐⭐⭐⭐⭐

Decoder-only 统一趋势，位置编码、激活函数、Normalization 位置差异。主流模型均采用 Decoder-only，但 Qwen/LLaMA 使用 Pre-Norm + RMSNorm + SwiGLU + RoPE，GPT 系列最早使用 Post-Norm + LayerNorm + GeLU + 可学习位置编码。

### Q2: Pre-Norm vs Post-Norm 有什么区别，为什么现在都用 Pre-Norm？⭐⭐⭐⭐⭐

Pre-Norm（Normalization 在 sublayer 之前）训练更稳定、梯度流动更好。Post-Norm（在 sublayer 之后）在深层网络中容易梯度消失/爆炸。LLaMA/Qwen 等主流模型全部使用 Pre-Norm（RMSNorm）。

### Q3: Transformer 的 Encoder 和 Decoder 各由什么组成？Decoder-only 少了什么？⭐⭐⭐⭐

Encoder：Self-Attention + FFN，双向注意力。Decoder：Masked Self-Attention + Cross-Attention + FFN。Decoder-only 模型去掉了 Cross-Attention（因为没有 Encoder 输出可供 cross-attend），只保留 Masked Self-Attention + FFN。

### Q4: Multi-Head Attention 的计算步骤？时间复杂度？⭐⭐⭐⭐⭐

计算步骤：每个头的 Q/K/V 线性变换 → 缩放点积 → softmax → 加权求和 → 拼接所有头 → 输出投影。时间复杂度 O(n^2 * d)，其中 n 为序列长度，d 为 hidden dimension。

### Q5: 为什么 Attention 要除以 sqrt(d_k)？⭐⭐⭐⭐

防止点积方差过大导致 softmax 进入梯度饱和区（梯度消失）。当 d_k 较大时，QK^T 的方差 ≈ d_k，除以 sqrt(d_k) 将方差归一化到 1，softmax 的梯度保持健康。

### Q6: BPE tokenizer 的训练流程？vocab_size 怎么选？⭐⭐⭐⭐

初始化字符级词表 → 统计所有相邻 token pair 的频率 → 合并频率最高的 pair 为新 token → 重复直到达到目标 vocab size。vocab_size 通常选 32K-128K，太小则序列变长效率低，太大则 embedding 矩阵过大且低频 token 训练不充分。

### Q7: Tokenizer 的 vocab_size 太小/太大分别有什么问题？⭐⭐⭐

太小：序列变长、自回归效率低、语义单元被过度拆分。太大：embedding 矩阵大显存占用增加、低频 token 训练不充分导致表示质量差。

### Q8: GQA（Grouped Query Attention）是什么？为什么省显存？⭐⭐⭐⭐

将 KV head 数量减少为 Q head 数量的 1/n，多个 Q head 共享同一组 KV head。减少 KV cache 大小（KV cache 大小正比于 KV head 数量），在 MHA 的质量和 MQA 的速度之间取得平衡。Qwen3 使用 GQA。

### Q9: RoPE 位置编码的原理？为什么优于绝对位置编码？⭐⭐⭐⭐⭐

通过复数旋转矩阵编码位置信息，使 attention score q_m^T k_n 只依赖于相对位置 (m-n)。优势：隐式相对位置编码、外推性好（训练长度外可继续有效）、不需要额外可学习参数。

### Q10: RMSNorm 和 LayerNorm 的区别？⭐⭐⭐⭐

LayerNorm 做 mean centering + variance scaling。RMSNorm 只做 variance scaling 去掉 mean centering，计算更快（少算均值），效果相当。LLaMA/Qwen 均使用 RMSNorm。

```python
import torch
import torch.nn.functional as F

def scaled_dot_product_attention(Q, K, V, mask=None):
    d_k = Q.size(-1)
    scores = torch.matmul(Q, K.transpose(-2, -1)) / math.sqrt(d_k)
    if mask is not None:
        scores = scores.masked_fill(mask == 0, float('-inf'))
    attn_weights = F.softmax(scores, dim=-1)
    output = torch.matmul(attn_weights, V)
    return output, attn_weights
```

## Day 2：SFT + LoRA/QLoRA

### 复习目标
- 透彻理解 SFT 的 loss、数据格式、训练技巧
- 能解释 LoRA 的数学原理、初始化策略、α 和 r 的含义
- 能对比 QLoRA vs LoRA 的额外技术（NF4 量化、双重量化、分页优化器）

### Q1: SFT 的 loss 公式是什么？label_mask 怎么做？⭐⭐⭐⭐⭐

Cross-entropy on response only：L_SFT = -1/|R| * Σ_{t∈R} log π_θ(y_t | x, y_<t)。prompt 部分的 label 设为 -100（CrossEntropyLoss 的 ignore_index），只对 response token 计算 loss。本质是 teacher-forcing：每个位置预测下一个 token。

### Q2: SFT 数据和预训练数据有什么区别？⭐⭐⭐⭐

SFT 是 instruction-response pair，模型学习的是"给定指令→生成回复"。预训练是原始文本 next-token prediction，模型学习的是通用语言分布。SFT 数据更结构化、更小规模、更高质量。

### Q3: 为什么 SFT 阶段通常只训练 1-3 epoch？⭐⭐⭐⭐

SFT 数据量少（通常几千到几十万），多 epoch 容易过拟合导致：丧失生成多样性、产生幻觉（记住了训练数据的 pattern）、对未见过的 prompt 泛化差。

### Q4: LoRA 的数学公式 W' = W + ΔW = W + BA 中，A 和 B 的初始化策略是什么？为什么？⭐⭐⭐⭐⭐

A 用高斯/均匀初始化（非零），B 用零初始化。这样初始时 ΔW = BA = 0，模型输出完全等于预训练模型。如果 A 也初始化为零，梯度对称导致无法有效训练。

### Q5: LoRA 中 rank r 怎么选？α 是什么？⭐⭐⭐⭐

r 通常选 8-64（我们的项目 r=16）。α 是缩放因子，实际学习到的 ΔW = (α/r) * BA。α/r 控制 LoRA 更新的幅度。r 越大可学习参数越多但过拟合风险增加，r=8 通常就够用。

### Q6: QLoRA 的 NF4 量化原理？⭐⭐⭐⭐

NormalFloat4：针对正态分布权重的最优 4bit 量化格式。不同于 INT4 的均匀量化，NF4 的分位点按正态分布的概率密度设计——在概率密度高的区域（均值附近）分得更细，密度低的区域（尾部）分得更粗，信息损失最小。

### Q7: QLoRA 的双重量化是什么？⭐⭐⭐

对量化常数（每个 block 有自己的 scale 和 zero-point）本身再做一次量化。因为量化常数也是浮点数，在大量 block 下会占可观显存。双重量化将量化常数从 FP32 压缩到 FP8，进一步节省约 0.4 bytes/param。

### Q8: 全量微调 vs LoRA vs QLoRA 的显存和效果对比？⭐⭐⭐⭐

全量微调显存最大（8B 模型约需 64-192GB），LoRA 次之，QLoRA 最小（8B 模型约 12GB）。效果差距：QLoRA vs 全量微调在大多数 benchmark 上差距 <2%，性价比极高。

### 易错点
- LoRA 的 A 初始化为零是错的——A 高斯初始化、B 零初始化
- QLoRA 不仅省模型权重显存——还有双重量化、分页优化器、LoRA 四项技术叠加省显存
- SFT 不是 epoch 越多越好——通常 1-3 epoch，需要监控 validation loss

**代码2：LoRA 层前向传播**
```python
class LoRALinear(nn.Module):
    def __init__(self, in_features, out_features, r=8, alpha=16, dropout=0.0):
        super().__init__()
        self.linear = nn.Linear(in_features, out_features, bias=False)
        self.lora_A = nn.Parameter(torch.randn(r, in_features) * 0.02)
        self.lora_B = nn.Parameter(torch.zeros(out_features, r))
        self.scaling = alpha / r
        self.dropout = nn.Dropout(dropout)

    def forward(self, x):
        base = self.linear(x)
        lora_out = (self.dropout(x) @ self.lora_A.T @ self.lora_B.T) * self.scaling
        return base + lora_out
```

## Day 3：DPO + Reward Model

### 复习目标
- 能用数学推导 DPO loss（从 BT 模型到最优策略到 DPO loss）
- 能解释 DPO 与 RLHF/PPO 的区别和联系
- 能讨论 DPO 的超参（β）和数据构造要点

### Q1: DPO 的 loss 公式是什么？每个符号的含义？⭐⭐⭐⭐⭐

L_DPO = -E[log σ(β(log π_θ(y_w|x) - log π_θ(y_l|x) - (log π_ref(y_w|x) - log π_ref(y_l|x))))]。其中 π_θ 是当前策略，π_ref 是参考策略（frozen），y_w 是 chosen，y_l 是 rejected，β 控制偏离 ref 的强度。

### Q2: DPO 的 β 越大/越小意味着什么？⭐⭐⭐⭐

β 大：更接近 reference model，策略更新保守，不容易过拟合但可能欠拟合。β 小：更激进地拉开 chosen/rejected 的偏好差距，但可能过拟合和 reward hacking。我们的项目 β=0.1（通过 grid search {0.01, 0.05, 0.1, 0.5, 1.0} 选出）。

### Q3: DPO 的梯度分析告诉了我们什么？⭐⭐⭐⭐

∇_θ L_DPO = -β E[(1-σ(β * log_ratio_diff)) * (∇_θ log π_θ(y_w) - ∇_θ log π_θ(y_l))]。梯度方向是"增大 chosen 概率 + 减小 rejected 概率"，加权因子 (1-σ(...)) 是 reward error——当模型已经能区分时误差小→梯度小，反之梯度大。自适应的加权机制。

### Q4: BT 模型（Bradley-Terry）是什么？DPO 怎么利用它的？⭐⭐⭐⭐

BT 模型将成对偏好概率建模为 P(y_w ≻ y_l) = σ(r(y_w) - r(y_l))。DPO 证明这个约束优化问题有闭式解：r*(x,y) = β log(π*(y|x)/π_ref(y|x)) + β log Z(x)。代入 BT 模型后 reward 被消掉，得到只需 π_θ 和 π_ref 的 loss。

### Q5: DPO 数据需要什么格式？chosen/rejected 应该怎么构造？⭐⭐⭐⭐

三元组 (prompt, chosen, rejected)。差异要"subtle but meaningful"——chosen 和 rejected 都在内容上可接受，但 chosen 在安全性/完整性/风格上略优。差异太大（一个完美一个明显错误）学到的信号太粗粒度；差异太小（几乎一样）没有偏好信号。

### Q6: DPO 训练应该多少个 epoch？为什么容易过拟合？⭐⭐⭐⭐

通常 1-3 epoch。DPO 容易过拟合是因为：偏好数据规模小（10K 量级）、implicit reward 信号强烈、缺少显式 KL 约束。reward accuracy > 0.9 通常意味着过拟合——生成质量反而下降。

### Q7: DPO vs PPO 的优缺点对比？⭐⭐⭐⭐⭐

DPO：简单稳定，不需要显式 RM，训练成本低，off-policy 用历史数据。PPO：更灵活可迭代优化，on-policy 缩小分布偏移，效果上限更高。但 PPO 需要 4 个模型（policy/ref/reward/value），训练不稳定，工程复杂。

### Q8: Off-Policy DPO vs On-Policy DPO 的区别？⭐⭐⭐

Off-Policy DPO（标准）：用预先收集的历史偏好数据训练，成本低但存在分布偏移。On-Policy DPO（Iterative DPO/OPD）：用当前模型采样生成新偏好对，数据分布与当前策略一致，效果更好但成本高 3-5 倍。

### 易错点
- DPO 需要 reference model——ORPO 和 SimPO 才不需要
- reward accuracy 高不等于模型好——可能是过拟合，需要看实际生成质量
- DPO 可能导致幻觉增加——reward 偏好"确定自信"的输出，在知识薄弱区变成"自信编造"

### 必写代码（3段）

**代码1：DPO loss（从零实现）**
```python
def dpo_loss(policy_chosen_logps, policy_rejected_logps,
             ref_chosen_logps, ref_rejected_logps, beta=0.1):
    policy_log_ratio = policy_chosen_logps - policy_rejected_logps
    ref_log_ratio = ref_chosen_logps - ref_rejected_logps
    logits = policy_log_ratio - ref_log_ratio
    losses = -F.logsigmoid(beta * logits)
    chosen_rewards = beta * (policy_chosen_logps - ref_chosen_logps).detach()
    rejected_rewards = beta * (policy_rejected_logps - ref_rejected_logps).detach()
    reward_acc = (chosen_rewards > rejected_rewards).float().mean()
    return losses.mean(), reward_acc
```

## Day 4：RAG + Safety-RAG

### 复习目标
- 理解 RAG 的标准流程和变体（Naive RAG → Advanced RAG → Modular RAG → Agentic RAG）
- 深度学习 Safety-RAG 的设计（检索 → 比对 → 修正 → 验证）
- 理解检索增强为什么能减少幻觉

### Q1: 标准 RAG 流程分几步？每步的挑战是什么？⭐⭐⭐⭐⭐

Indexing（文档切分+向量化+索引构建）→ Retrieval（query 向量化+相似度检索）→ Augmentation（拼入 prompt）→ Generation（LLM 生成）。挑战：检索不准、context 太长导致 lost in the middle、检索知识与模型参数知识冲突。

### Q2: embedding model 怎么选？bge-large vs text2vec 的区别？⭐⭐⭐⭐

中文医疗场景 bge-large-zh-v1.5 效果更好，1024 维向量。选择考量：MTEB 中文榜单排名、领域适配（是否需要继续训练）、模型大小（推理速度）、维度（存储成本）。

### Q3: 检索 chunk 大小怎么定？overlap 的作用？⭐⭐⭐

医疗知识 256-512 token/chunk，overlap 50-128 token。太小则语义不完整，太大则检索精度下降。overlap 防止关键信息被切分边界切断。

### Q4: Hybrid Search（混合检索）是什么？⭐⭐⭐⭐

Dense retrieval（向量语义检索）+ Sparse retrieval（BM25 关键词检索）组合。RRF（Reciprocal Rank Fusion）融合两路结果。Dense 捕捉语义相关，Sparse 捕捉精确匹配，互补提高召回率。

### Q5: Safety-RAG 跟你普通的 RAG 有什么区别？⭐⭐⭐⭐⭐

核心差异：多了一个 safety layer——检索 → 生成 → 验证 →（如需要）修正。标准 RAG 盲目信任检索结果和模型生成，Safety-RAG 让两者互相校验：verifier 比对生成内容与检索知识是否一致，不一致则用检索知识修正。

### Q6: RAG 的幻觉为什么比纯生成少？⭐⭐⭐

RAG 提供了外部知识 anchor——模型被 prompt 约束在检索内容的范围内生成，而不是依赖内部参数中可能错误的知识。但这不意味着 RAG 消除幻觉——检索错了依然可能产生幻觉。

### Q7: RAG 检索错了怎么办？怎么评估检索质量？⭐⭐⭐⭐

引入 reranker 对 top-k 重排序、多路召回交叉验证、置信度阈值（similarity < 阈值时标记"知识库覆盖不足"）、知识源权威等级。评估用 Recall@K 和 MRR。

### 易错点
- RAG 不能完全消除幻觉——可能引入 retrieval error / attribution error 等新类型幻觉
- "Lost in the middle"问题：LLM 对 prompt 中间位置的信息关注度低于开头和结尾
- Chunk 不是越小越好——需要在语义完整性和检索精度间平衡

**代码1：简单的向量检索流程**
```python
import faiss
from sentence_transformers import SentenceTransformer

class SimpleRetriever:
    def __init__(self, model_name="BAAI/bge-large-zh-v1.5"):
        self.encoder = SentenceTransformer(model_name)
        self.index = None
        self.chunks = []

    def build_index(self, documents, chunk_size=256, overlap=50):
        from langchain.text_splitter import RecursiveCharacterTextSplitter
        splitter = RecursiveCharacterTextSplitter(
            chunk_size=chunk_size, chunk_overlap=overlap)
        self.chunks = splitter.split_documents(documents)
        embeddings = self.encoder.encode(
            [c.page_content for c in self.chunks], normalize_embeddings=True)
        self.index = faiss.IndexFlatIP(embeddings.shape[1])
        self.index.add(embeddings.astype('float32'))

    def retrieve(self, query, top_k=5):
        q_emb = self.encoder.encode([query], normalize_embeddings=True)
        scores, indices = self.index.search(q_emb.astype('float32'), top_k)
        return [(self.chunks[i].page_content, scores[0][j])
                for j, i in enumerate(indices[0])]
```

```python
class SafetyRAGVerifier:
    def __init__(self, llm, retriever):
        self.llm = llm
        self.retriever = retriever

    def verify(self, query, model_response):
        retrieved = self.retriever.retrieve(query, top_k=5)
        verification_prompt = f"""
        请比对以下模型回答与医学知识库内容是否一致：
        模型回答：{model_response}
        知识库参考：{retrieved}
        请指出：1. 是否存在事实错误 2. 是否存在幻觉（编造不存在的信息）3. 安全等级（safe / needs_revision / unsafe）
        """
        verdict = self.llm.generate(verification_prompt)
        if "unsafe" in verdict or "needs_revision" in verdict:
            corrected = self.llm.generate(
                f"基于以下知识重新回答：\n知识：{retrieved}\n问题：{query}")
            return corrected, verdict, retrieved
        return model_response, verdict, retrieved
```

## Day 5：LLM-as-Judge + 医疗安全

### 复习目标
- 理解 LLM-as-Judge 的设计原则和常见 bias
- 能设计合理的评测 prompt 和评分维度
- 理解医疗 AI 的特殊安全要求

### Q1: LLM-as-Judge 常见的 bias 有哪些？怎么缓解？⭐⭐⭐⭐⭐

Position bias（偏好第一个位置的回答）、Verbosity bias（偏好更长的回答）、Self-enhancement bias（偏好自己模型生成的回答）。缓解方法：交换位置做 swap augmentation、控制输出长度、使用第三方模型做 judge。

### Q2: 让 LLM 打分 vs 做 pairwise 对比，哪个更好？⭐⭐⭐⭐

Pairwise 更稳定可靠。绝对打分受模型 calibration 影响大（某些 judge 天生打分偏高或偏低）。Pairwise 对比直接给出偏好判断，统计上更 robust。

### Q3: 怎么验证你的 LLM-as-Judge 是靠谱的？⭐⭐⭐⭐

与人工标注计算 Spearman/Kendall 秩相关系数。Spearman > 0.7 可接受。我们的项目 accuracy 维度 Spearman 达 0.78，但 safety 维度只有 0.62——说明 LLM-Judge 在安全判断上还有 bias。

### Q4: 医疗评测的特殊维度有哪些？⭐⭐⭐⭐

准确性（回答是否与临床知识一致）、安全性（是否避免处方建议和不恰当确定性表述）、完整性（是否满足用户需求）、合规性（是否符合医疗法规）、不确定性表达（是否适当表达"建议就医"等）。

### Q5: 什么是医疗模型的"过度拒答"问题？怎么检测？⭐⭐⭐

安全设计过强导致模型对 benign 医疗问题（如"维生素 C 有什么作用"）也拒绝回答。用 benign query set 测试拒答率，应 <5%。同时用 adversarial query set 测试应拒答问题的拒答率，应 >90%。

### Q6: 模型给出处方级建议的风险在哪里？怎么在 prompt 里避免？⭐⭐⭐

法律风险（无处方权）+ 医疗风险（个体差异导致错误）。在 system prompt 中明确'不提供处方建议，仅提供知识参考'，训练数据中加入拒答样本，输出后加"仅供参考，请遵医嘱"。

### Q7: RAG 检索到错误知识怎么办？怎么设计容错机制？⭐⭐⭐⭐

多源检索交叉验证、置信度阈值、知识源权威等级（指南 > 教科书 > 科普）、人工审核高风险回答。设计假设"检索会出错"——因此有五道防线：reranker + verifier + 多源验证 + 权威等级 + 置信度阈值。

### Q1: vLLM 的 PagedAttention 是什么？为什么能提升吞吐？⭐⭐⭐⭐⭐

将 KV cache 切分为固定大小的 page（block），按需分配和动态回收，而非预先分配连续显存。解决传统 KV cache 的内存碎片问题（利用率从 20-30% 提升到 80-90%），同等显存可支撑 2-4 倍并发。

### Q2: vLLM 的 continuous batching 是什么？⭐⭐⭐⭐

不等待整个 batch 中所有请求完成才释放，而是哪个请求完成了立即从 batch 移除，同时加入新请求。相比 static batching（等整个 batch 完成），GPU 利用率更高，尤其在长短序列混合场景下吞吐提升 2-5 倍。

### Q3: vLLM vs TGI vs TensorRT-LLM 的对比？⭐⭐⭐

vLLM：开源易用、PagedAttention + continuous batching、社区活跃。TGI：HuggingFace 原生生态好、支持 watermarking。TensorRT-LLM：NVIDIA 官方、极致性能、但配置复杂。

### Q4: 混合精度训练（fp16/bf16）的区别？什么场景用哪个？⭐⭐⭐⭐

fp16: 1s+5e+10m，范围约 6e-8 到 65504，需要 loss scaling 防止梯度 underflow。bf16: 1s+8e+7m，范围同 fp32（约 10^38），不需要 loss scaling。大模型训练首选 bf16（更稳定），推理可选 fp16（精度稍高）。

### Q5: 梯度累积（gradient accumulation）的作用？⭐⭐⭐⭐

将大 batch 拆分为多个 micro-batch，每个 micro-batch 前向+反向计算梯度并累加，多次后执行一次 optimizer.step()。等价于大 batch 训练但显存只需 micro-batch 量级。

### Q6: ZeRO 的三个 stage 分别优化什么？⭐⭐⭐⭐⭐

ZeRO-1：分片优化器状态（optimizer states），省约 4x 显存。ZeRO-2：+ 分片梯度，省约 8x。ZeRO-3：+ 分片参数，省约 N 倍（N=GPU 数），但通信量增加约 50%。

### Q7: Flash Attention 为什么快？⭐⭐⭐⭐⭐

三个核心技术：Kernel Fusion（将多个 CUDA kernel 融合为一个，减少 HBM 读写）、Tiling（将 attention 矩阵分块计算，避免存储完整 n×n 矩阵）、Recomputation（反向传播时不存储 attention 矩阵，需要时重算）。综合节省 10-20 倍显存带宽。

### Q8: torch.compile / DeepSpeed / FSDP 分别是什么？什么场景用？⭐⭐⭐

torch.compile：PyTorch 2.0 图编译加速，通用优化。DeepSpeed：ZeRO 分布式训练框架，大规模训练标配。FSDP：PyTorch 原生 ZeRO-3 实现，与 PyTorch 生态深度集成。

```python
def sft_collate_fn(batch, tokenizer, max_length=2048, pad_token_id=0):
    prompts = [item["prompt"] for item in batch]
    responses = [item["response"] for item in batch]
    full_texts = [p + r for p, r in zip(prompts, responses)]
    tokenized = tokenizer(
        full_texts, max_length=max_length, truncation=True,
        padding=True, return_tensors="pt"
    )
    labels = tokenized["input_ids"].clone()
    prompt_lengths = [len(tokenizer.encode(p, add_special_tokens=False))
                      for p in prompts]
    for i, plen in enumerate(prompt_lengths):
        labels[i, :plen] = -100
    return {
        "input_ids": tokenized["input_ids"],
        "attention_mask": tokenized["attention_mask"],
        "labels": labels,
    }
```

**代码3：手写完整的训练循环（PyTorch 原生）**
```python
def train_epoch(model, dataloader, optimizer, scheduler, device):
    model.train()
    total_loss = 0
    progress_bar = tqdm(dataloader)
    for step, batch in enumerate(progress_bar):
        input_ids = batch["input_ids"].to(device)
        attention_mask = batch["attention_mask"].to(device)
        labels = batch["labels"].to(device)
        outputs = model(input_ids=input_ids, attention_mask=attention_mask, labels=labels)
        loss = outputs.loss
        loss = loss / 4  # gradient accumulation steps
        loss.backward()
        if (step + 1) % 4 == 0:
            torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)
            optimizer.step()
            scheduler.step()
            optimizer.zero_grad()
        total_loss += loss.item() * 4
        progress_bar.set_postfix({"loss": loss.item() * 4})
    return total_loss / len(dataloader)
```

### Q1: 你这个项目的算法性体现在哪里？⭐⭐⭐⭐⭐

Teacher 数据生成策略设计 + 偏好数据构造 + Safety-RAG 验证管线 + 幻觉分析→方案设计→效果验证的闭环。不是调包——是从问题发现到因果分析到方案设计的完整算法思维链。

### Q2: 为什么不用 PPO/GRPO？⭐⭐⭐⭐⭐

DPO 适合 10K 规模 + 资源约束（RTX 5090 32GB 单卡）。PPO 需要 4 个模型同时维护（reward model + value model + policy + reference），GRPO 虽去掉了 value model 但仍需 reward model + group sampling。在有限资源和时间下，DPO 是性价比最高的选择。升级路径：Iterative DPO → OPD → GRPO。

### Q3: 3 个样本说服不了人怎么办？⭐⭐⭐⭐⭐

诚实承认样本量限制 + 强调观察到的现象有意义 + 说明这是探索性工作 + 如果有资源会系统性评估。这不是统计显著结论而是有价值的信号——正确表述是"观察到的幻觉案例在 RAG 修复后不再出现"而非"幻觉下降 66.7%"。

### Q4: teacher 模型也会错怎么办？⭐⭐⭐⭐

数据滤筛机制：医学知识库交叉验证 + 人工抽检 + 多样性筛选。teacher 不是 ground truth 而是高质量参考。整个 pipeline 设计假设没有任何单一来源是完美的——每个阶段都有独立的校验机制。

### Q5: DPO 为什么会放大幻觉？⭐⭐⭐⭐⭐

DPO 的 implicit reward 偏好"确定自信"的回答风格——chosen 通常比 rejected 更完整、更自信。模型学会：在不确定时与其说"我不确定"（可能被 rejected），不如编造一个看似专业的回答（更像 chosen）。本质是 reward hacking——reward 过度优化了"确定性"而损害了"真实性"。

### Q6: 你的项目和普通微调有什么区别？⭐⭐⭐⭐

全流程闭环：数据→训练→安全→评测→部署。不只是做了 SFT——而是 SFT 后发现安全需求做 DPO，DPO 后发现幻觉做 Safety-RAG。每个阶段由前一个阶段的发现驱动，这是真正的 research loop。

### Q7: 如何证明你的算法能力？⭐⭐⭐⭐

能从第一性原理推导 DPO loss + 理解 RLHF 的数学基础 + 知道每个设计选择的 trade-off + 能从实验现象出发做因果分析。算法能力 = 理解原理 + 分析问题 + 设计方案。

### Q8: 如何证明你的工程能力？⭐⭐⭐⭐

### Q9: LLM-as-Judge 不可靠怎么办？⭐⭐⭐⭐

多 judge 交叉验证 + 与人工标注对标（Spearman）+ 安全维度引入规则辅助 + 接受局限性。LLM-as-Judge 是"80%可信"的评测工具——用得好的前提是知道它在哪些地方不可信。

### Q10: 这个项目最能体现你算法能力的地方是什么？⭐⭐⭐⭐⭐

Safety-RAG 的设计——从观察到 DPO 后的幻觉现象（empirical observation），到分析幻觉产生机制（reward hacking），到设计验证-修正闭环（retrieval + verification + correction），到实验验证（3 个案例修复成功）。完整的算法思维链。
